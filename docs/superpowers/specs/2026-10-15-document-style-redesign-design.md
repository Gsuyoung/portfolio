- 작성일: 2026-10-15
- 대상 레포: `Gsuyoung/portfolio` (브랜치 `feature/initial-setting`)
- 승인된 시안: https://claude.ai/artifact/WKRNbm1APmXhGYLVdxS7Lt
- 레퍼런스: 노트폴리오 「Special Album 산과들 LEEYOUNG」 (분위기와 디자인 언어만 참고, 이미지·로고·일러스트는 사용하지 않음)

## 1. 목적과 성공 기준

**목적**: 백엔드 개발자 구수영의 포트폴리오를 **최대한 빨리 지원서에 첨부할 수 있는 상태**로 공개한다.

**성공 기준**

1. 정식 주소(Vercel, `main` 브랜치)에서 사이트가 열린다.
2. 공개된 페이지에 `TODO`가 하나도 없다.
3. About, 경력이 채워져 있고, 트러블슈팅이 들어간 대표 프로젝트가 1개 이상 있다.
4. 데스크톱(1366px)과 모바일(375px)에서 가로 스크롤 없이 읽힌다.

## 2. 범위

**이번에 하는 것**

- 현재 B+C 디자인(네이비 사이드바)을 승인된 서류철 스타일로 **교체**
- 메인 페이지: 책상 위 콜라주 첫 화면 + "개발자 이력 기록부" 양식 본문
- 프로젝트 상세: "기술 명세서" 문서
- 배포 기본값: 사이트 주소(`site`) 설정, 파비콘, 링크 미리보기(OG) 이미지, 404 페이지
- 내용 점검 스크립트 (`TODO` 남아 있으면 실패)
- Vercel 미리보기 배포 → 기준 충족 시 `main` 병합

**이번에 하지 않는 것**

- 노션 자동 연동, CMS, 다국어, 라이트/다크 전환, 방문자 분석, 블로그
- 콜라주 종이를 끌어서 옮기는 등의 인터랙션

## 3. 데이터 구조

내용과 화면은 지금처럼 분리한다. 기존 데이터 파일은 그대로 쓰고 필드만 추가한다.

### `src/data/profile.ts` (추가 필드)

| 필드 | 용도 | 비어 있을 때 |
|---|---|---|
| `nameEn` | 레터헤드의 영문 이름 (`GU SUYOUNG`) | 필수 |
| `letter` | 첫 화면 서신 본문, 문단 배열 | `about` 을 사용 |
| `docNo` | 이력 기록부 문서 번호 (`GSY-2026-001`) | 필수 |

`skills`, `experience`, `email`, `github`, `resume` 은 기존 그대로 쓴다.

### 프로젝트 Markdown (`src/content/projects/*.md`)

기존 스키마를 유지한다. 화면에서 쓰는 방식만 정한다.

- **파일 번호**: `order` 순으로 정렬한 뒤 `FILE 01`, `FILE 02` … 를 자동으로 붙인다.
- **"검토 완료" 도장**: `troubleshooting` 이 1개 이상인 프로젝트 카드에만 찍는다. 장식이 아니라 "깊이 있는 기록이 있는 프로젝트"라는 정보다.
- **조항 번호**: 상세 페이지 본문의 `##` 제목마다 `제1조`, `제2조` … 를 CSS 카운터로 붙인다. 트러블슈팅과 배운 점은 본문 다음 조항으로 이어서 번호를 매긴다.
- **도면**: 본문의 ```` ```text ```` 코드 블록을 모눈 배경의 도면 스타일로 보여준다. 이미지(`![구성도](/images/xxx.png)`)를 쓰면 같은 도면 틀 안에 넣는다.

## 5. 페이지 구성

### 메인 `/`

1. **책상 콜라주**: 표지(도트 이름 + 직무 + 바코드), 서신(자기소개 + 날짜 + 서명), 도면(시스템 구성 일러스트), 금속 태그(`GSY`), 라임 스티커.
2. **개발자 이력 기록부**: 서류철 탭(01 PROFILE / 02 PROJECTS / 03 CONTACT, 각 섹션으로 이동하는 링크), 문서 머리(이름·직무·문서 번호), §01 소개, §02 보유 기술, §03 경력, §04 프로젝트, §05 연락처.
3. 프로젝트가 0개이면 §04 에 "프로젝트 기록을 준비하고 있습니다." 빈 칸 양식을 보여준다.
4. 이력서 버튼은 지금처럼 파일이나 링크가 있을 때만 보인다.

### 프로젝트 상세 `/projects/{파일이름}/`

1. 명세서 머리: `Technical Specification · FILE NN`, 제목, 한 줄 소개, 결재란(작성·검토는 서명, 승인은 빈칸 "YOU?").
2. 메타: 기간, 역할, 팀, 기술, 레포 링크.
3. 본문 조항(Markdown) → 트러블슈팅 조항 → 배운 점 조항.
4. 하단 문서 꼬리: 수치 측정 환경 안내 + 문서 번호.

### 404

찢어진 서류 한 장: "요청하신 문서를 찾을 수 없습니다" + 메인으로 가는 링크.

## 6. 반응형과 접근성

- **900px 이하**: 콜라주 종이들이 세로로 겹쳐 쌓이고 기울기가 줄어든다. 양식 칸은 한 줄씩 아래로 내려간다. 경력 표는 표 안에서만 가로 스크롤.
- **대비**: 종이 위 글자는 `ink`(#141414) 기준. 라임 위에는 항상 `ink` 글자.
- **모션**: 도트 글자가 찍히는 짧은 연출(0.6초)만 넣고, `prefers-reduced-motion` 이면 바로 완성된 상태로 그린다. 연출 전에도 내용은 화면에 있다.
- **키보드**: 모든 링크에 라임 포커스 테두리.

## 7. 배포 방식

미리보기를 먼저 하고, 기준을 넘으면 정식 공개한다.

1. Vercel에 레포 연결 (사용자가 직접 로그인·Import). `feature/initial-setting` 은 미리보기 주소로 배포된다.
2. 디자인 적용과 내용 채우기를 병행한다.
3. `npm run check:content` 가 통과하고 1장의 성공 기준을 모두 만족하면 `main` 에 병합해 정식 공개한다.

## 8. 검증

- `npm run build` 성공
- `npm run check:content`: 공개 대상(`draft: false`) 파일과 `profile.ts` 에 `TODO` 가 있으면 실패
- 데스크톱 1366px, 모바일 375px 스크린샷으로 겹침·가로 스크롤 확인 (메인, 상세, 404)
- 배포 후 미리보기 주소에서 링크(레포, GitHub, 이메일, 이력서) 확인

## 9. 확정된 결정 (2026-10-15)

1. **학원 프로젝트**: CA2SA(`ca2sa.md`)와 AcaMatch(`studybridge.md`)는 규모가 큰 프로젝트라 **포함한다**. 새 양식에 맞게 두 파일을 손봐도 된다. 단, 원문이 지킨 원칙(커밋·코드로 확인된 내용만 쓰고, 확인되지 않은 수치·트러블슈팅은 지어내지 않음)은 유지한다. 두 파일 모두 `troubleshooting` 이 비어 있으므로 "검토 완료" 도장 없이 표시되고, 성공 기준 3(트러블슈팅이 있는 대표 프로젝트)은 사용자가 실제 사례를 알려줘야 채울 수 있다.
2. **서명**: 이미지 없이 영문 이름(`Suyoung Gu`)을 고정폭 이탤릭으로 표시한다. `signature` 필드는 만들지 않는다.
3. **사이트 주소**: 무료 Vercel 기본 주소(`*.vercel.app`)를 쓴다. 정확한 주소는 Vercel 연결 후 `astro.config.mjs` 의 `site` 에 넣는다.
