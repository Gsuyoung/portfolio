## 프로젝트 소개

재직 중인 회사의 고객사 프로젝트로, 운영 중인 **대학교 부트캠프 홈페이지**(사용자 사이트 + 관리자 페이지)의 백엔드를 기존 개발자에게서 넘겨받아 유지보수하고 있습니다. 모든 작업은 Swagger로 API를 테스트한 뒤 프론트엔드와 연동해 확인했습니다.

프로젝트는 기존 개발자가 처음부터 개발해 왔기 때문에, 아래 내용은 **넘겨받은 이후 직접 수행한 작업**만 정리했습니다. 회사 프로젝트라 소스 코드와 고객사 정보는 공개하지 않습니다.

## 직접 수행한 작업

| 작업 | 내용 |
| --- | --- |
| 팝업 순위 오류 | 일괄 수정 쿼리 이후 다시 조회하는 순서를 바로잡아 순위 변경이 반영되게 수정 |
| 팝업 종료일 표시 | 저장값(다음 날 0시)은 유지하고 조회 응답에서만 설정한 날짜로 변환 |
| 본문 이미지 삽입 | 미디어 업로드 API(이미지 URL 반환), Tika로 실제 파일 형식 검사, jsoup 기반 HTML Sanitizer 신규 작성 |
| 첨부파일 정책 | 신청 첨부 최대 3 · 4개 → 10개 통일, 요청 전체 크기 제한 함께 조정, `.hwpx` 허용 |
| 이수증 제출 서류 | 학과 · 시작 / 종료 학기 컬럼 추가, 첨부파일 테이블 신설, 첨부 수정 · 삭제 API, 목록 · 상세 응답 확장 |
| 로그인 시간 연장 | Access Token 15분 → 30분, 연장 버튼은 기존 재발급 API 활용, 화면 타이머 29분 협의 |
| 비고 선택 입력 | 상태 변경 DTO의 `@NotBlank`가 DB의 NULL 허용과 어긋나던 문제 수정 |

## 본문 이미지 삽입 흐름

```text
에디터에서 이미지 선택 ─▶ 미디어 업로드 API ─▶ Tika로 실제 파일 형식 검사 ─▶ 저장 후 이미지 URL 반환
                                                                              │
게시글 저장 ◀─ HTML Sanitizer로 허용 태그 · 속성만 남김 ◀─ 본문 HTML에 URL 삽입 ◀─┘
```

이미지 삽입은 업로드 하나가 아니라 **검증 → 저장 → URL 반환 → 본문 포함 → 화면 표시**까지 이어지는 흐름 전체를 봐야 했습니다. HTML 태그가 들어가면서 본문 길이 제한도 5,000자에서 20,000자로 늘렸습니다.

## 화면 타이머를 서버보다 1분 짧게

```text
실제 Access Token 유효 시간 : 30분
관리자 화면 타이머          : 29분부터 시작
```

화면에 몇 초가 남았을 때 연장 버튼을 눌러도, 요청이 서버에 도착해 처리되는 사이에 서버 쪽 토큰이 먼저 만료될 수 있습니다. 그래서 화면 타이머를 1분 짧게 보여 주도록 프론트엔드와 협의했습니다. 화면 타이머는 사용성을 위한 장치이고, 실제 만료 판단은 서버의 토큰 검증 결과를 따릅니다.

## 첨부 개수와 요청 크기는 함께

신청 첨부를 최대 10개로 늘리면서 **요청 전체 크기 제한도 함께** 늘렸습니다. 개수만 늘리면 파일 여러 개를 올릴 때 요청 크기 제한에 먼저 걸리기 때문입니다.
