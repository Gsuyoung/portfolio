## 프로젝트 소개

재직 중인 회사에 입사해 처음 맡은 고객사 프로젝트입니다. **가맹점주용 서비스와 관리자용 백오피스**로 구성되어 있습니다. 제가 메인 담당이었고, 일정이 급해 백엔드 팀원들이 영역을 나누기보다 필요한 곳에 손을 보태 주는 방식으로 함께 개발했습니다.

회사 프로젝트라서 소스 코드와 고객사 정보, 내부 API 구조는 공개하지 않습니다.

```text
가맹점주 ──▶ 매출 대시보드 · 이상거래 리포트 · 거래내역 · 사업자 정보 · 알림 설정
관리자   ──▶ 회원 심사 · PG사 거래 엑셀 적재 · 외부 API Key 발급 · 전체 지표
외부 탐지 시스템 ──▶ 이상거래 리포트를 DB에 적재  (서비스는 이를 조회)
```

## PG사 엑셀 거래 적재

두 PG사의 엑셀은 같은 거래라도 표현 방식이 달랐습니다.

| 항목 | PG사 A | PG사 B |
| --- | --- | --- |
| 거래일시 | 한 셀 | 날짜 · 시간 두 셀 |
| 거래 상태 | 거래 응답 + 취소 응답 조합 | 승인 / 취소 / 승인거절 |
| 결제수단 | 컬럼 있음 | 비어 있으면 카드로 보정 |

```text
v1  사업자 전체 거래 조회 + 한 번에 저장      거래가 쌓일수록 조회량 · 메모리 증가
v2  파일 기간을 먼저 계산 → 그 기간만 조회     중복 검사 범위 축소 (파일을 두 번 읽는 2-pass)
v3  일정 건수마다 saveAll → flush → clear     영속성 컨텍스트 누적 완화
```

**대용량 파일 업로드 시도 기록**

| 시도 | 방법 | 결과와 이유 |
| --- | --- | --- |
| 1 | WorkbookFactory (기존 방식) | 실패 · 파일 전체를 메모리에 올려 읽는 방식 |
| 2 | 저장 배치 1000 → 500 → 100건 | 실패 · 저장 단위만 줄었고, 읽을 때 파일 전체를 올리는 문제는 그대로 |
| 3 | 스트리밍 리더 라이브러리 | 실패 · 구버전 라이브러리라 지원되지 않았고, .xlsx만 읽을 수 있음 |
| 4 | XSSFWorkbook | 실패 · .xlsx 전용 |
| 5 | EasyExcel | 실패 · 기존 POI 기반 코드와 함께 적용하지 못함 |
| 6 | 2-pass → 1-pass | 실패 · 중복 검사에 필요한 파일 기간을 미리 알 수 없어 구조 변경을 마무리하지 못함 |
| 결론 | 원본 파일을 4개로 나눠 업로드 | 적재 완료 · 근본 해결은 후속 과제 |

- **중복 기준**: 같은 승인번호라도 승인과 취소는 다른 거래라서 거래 상태까지 기준에 넣었습니다. 같은 파일 안의 중복 행도 막았습니다.
- **잘못된 파일은 전체 롤백**: 관리자가 고른 사업자와 파일의 상호명이 한 줄이라도 다르면 예외를 내고, 이미 저장한 묶음까지 전부 되돌렸습니다.
- **셀 타입**: 승인번호처럼 식별값은 숫자 셀이면 지수 표기나 앞자리 0이 사라질 수 있어 문자열로 보존했습니다. 알 수 없는 상태값은 행 번호를 남기고 업로드 전체를 실패시켰습니다. 잘못 분류된 거래가 매출과 이상거래 통계를 왜곡하기 때문입니다.

## 관리자 대시보드

- **유형 매핑**: 외부 탐지 시스템이 저장하는 유형은 8개, 화면 차트는 6개였습니다. DB 값은 그대로 두고 조회할 때 매핑했고, 데이터가 없는 유형도 0으로 항상 보여 줬습니다.
- **빈 달 채우기**: 월별 집계는 거래가 없는 달을 돌려주지 않아, 1 ~ 12월을 직접 채우고 없는 달은 0으로 보정했습니다.
- **전일 대비 증감률**: 전날 값이 0이면 나눗셈 오류가 나지 않도록 따로 처리했습니다.

## 데이터 접근 범위 제한

- 거래 상세를 ID 하나로만 조회하면 다른 사업자의 거래 ID를 넣어 볼 수 있습니다. **로그인한 회원의 사업자 정보를 조회 조건에 함께 넣어** 자기 데이터만 보이게 했습니다.
- 승인 대기 · 반려 회원은 토큰이 있어도 기능을 쓰지 못하도록 회원 상태까지 확인했습니다.

## 설정 API

- 설정이 아직 없는 신규 회원도 화면이 깨지지 않도록, 저장하지 않는 기본값으로 응답했습니다.
- 수정은 PATCH 의미대로 **값이 온 필드만 바꾸고, null은 변경 없음**으로 처리했습니다.

## 최종 배포

배포 파이프라인과 절차는 회사에 이미 구성되어 있었습니다. 저는 발급받은 호스팅 서버(카페24) 계정으로 Termius에서 접속해, 정해진 흐름대로 Nginx · DB · Redis를 설치하고 설정한 뒤 최종 배포를 진행했습니다. 처음 해 보는 서버 작업이라 단계마다 확인하며 진행했고, 배포 이후 유지보수도 맡고 있습니다.

```text
기존 배포 파이프라인 · 절차
   │
   └─▶ 운영 서버 접속 (Termius · 발급받은 IP · 계정)
         ├─ Nginx 설치 · 설정
         ├─ DB · Redis 설치 · 설정
         └─ 최종 배포 ─▶ 유지보수
```
