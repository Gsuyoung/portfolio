## 담당 영역 — 구매 데이터 설계

팀원들과 함께 **전체 ERD 설계에 참여**했고, 개인적으로는 **구매 · 교환 · 환불 테이블 설계**를 맡았습니다. 교환 · 환불은 테이블 설계까지 담당했고, 관련 기능 구현은 진행하지 않았습니다.

- 상품 구매 과정에서 생기는 구매 · 주문 정보와 관련 데이터의 관계를 설계했습니다.
- 구매 데이터가 출고 처리로 넘어가는 연결 구조를 설계했습니다.
- 구매 건을 기준으로 이어지는 교환 · 환불 테이블과 참조 관계를 설계했습니다.
- 다른 팀원이 설계한 도메인과 맞닿는 지점을 협의해 ERD에 반영했습니다.

## 조회 성능 개선 — 날짜 · 지역별 배송 상태

테스트 주제는 **날짜별 · 지역별 배송 상태 조회**였습니다. 같은 조회를 세 가지 방식으로 작성하고 `EXPLAIN`으로 실행 계획을 비교했습니다.

```text
단계   쿼리 방식              실행 계획                          응답
────   ─────────────────     ──────────────────────────────     ──────
v1     JOIN 단순 조회         일부 Full Table Scan                710ms
v2     MATCH ... AGAINST      대부분 Index 사용                   473ms
v3     MATCH + 서브쿼리        전부 Index 사용 + Covering Index    231ms
```

- FULLTEXT 인덱스와 `MATCH ... AGAINST`로 전체 스캔을 줄였습니다.
- 서브쿼리로 조회 범위를 먼저 좁혀, 필요한 컬럼을 인덱스만으로 읽는 **커버링 인덱스**가 되도록 했습니다.
- 응답 시간은 **710ms → 231ms로 약 67% 줄었습니다.**

가장 큰 테이블이 약 50만 건이라 체감 차이는 크지 않았습니다. 그래도 실행 계획이 Full Table Scan에서 커버링 인덱스로 바뀌는 과정을 직접 확인한 것이 이 프로젝트에서 얻은 가장 큰 경험입니다.
